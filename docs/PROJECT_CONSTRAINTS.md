# 项目约束

## 技术基线

- 引擎固定为 Godot 4.x；渲染器使用 **GL Compatibility**，以保证 Web 导出的兼容性。
- 首发目标为桌面浏览器，逻辑画布为 1920 × 1080，使用 `canvas_items` + `expand` 适配不同横屏宽高比。
- 面向 Web 的内容必须避免平台原生插件、线程依赖、运行时外部文件访问和未经评估的大型包体。
- 任何新增第三方插件、字体或素材必须具备明确的 Web 使用许可，并记录来源和许可。

## 体验与美术基线

- 所有游戏 UI 使用 `Control` 布局节点和主题变量；禁止把关键 UI 按固定屏幕像素硬编码。
- 交互状态至少覆盖：默认、悬停、按下、禁用、选中、成功、危险。视觉反馈应在 100 ms 内开始。
- 可读性优先：战斗/棋盘上的信息不得仅依赖颜色传达；危险色与普通状态须有形状、图标或文本差异。
- 特效应分层：背景氛围、可读性交互反馈、奖励/关键事件。棋盘信息上的特效不得遮挡格子内容。
- 采用程序化/可复用的 UI 与 VFX 资源；高频特效必须设上限、可池化，并在低性能设备上可降级。

## 工程约定

- `scenes/`：可复用场景；`scripts/`：行为代码；`assets/`：源资源；`themes/`：UI 主题；`vfx/`：粒子、shader 和特效场景；`tests/`：自动化测试。
- 每个玩法域独立组织：`board/`、`run/`、`combat/`、`relics/`、`ui/`。跨域通信通过明确定义的信号或数据对象，不直接查找深层节点路径。
- 随机内容必须使用可注入的种子；每局 run 保留种子，方便复现 bug 与分享。
- 棋盘和局外数值逻辑与表现分离，保证可测试并避免动画时序影响结果。
- 提交二进制资源时必须同时提交源文件或来源说明；生成目录 `build/` 不纳入版本控制。

## 性能预算（Web 首发）

- 目标：主流桌面浏览器稳定 60 FPS；关键交互帧优先级高于装饰性效果。
- 首屏避免加载整局内容；场景、音频与大型纹理按需加载。
- 纹理优先使用压缩与图集，避免不必要的透明大图；每次新增视觉资源后在 Web 导出物中检查体积。
- 每个新功能合入前至少在 Chromium 与 Firefox 的 Web 导出中验证一次。
